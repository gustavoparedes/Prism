# Reporting a problem

[Documentation home](../../README.md) | [Español](../es/reporting-problems.md)

Use the repository's Issues section for documentation corrections and
non-sensitive problem reports. Include:

1. The exact application version and input mode: E01, AD1, folder or live.
2. The host Windows version and architecture; for live, whether the process was elevated.
3. Minimal reproduction steps and expected versus observed behavior.
4. The affected artifact type, processing status and relevant sanitized diagnostics.
5. Whether the issue affects acquisition, extracted fields, timestamps or visualization.

Do not upload real evidence, `.pri` cases, hives, credentials, license keys or
unredacted private logs. Prefer a synthetic sample or a publicly available
reproduction corpus. A filename, username or source path can itself be sensitive.

For a suspected vulnerability, first arrange a private reporting channel with the
maintainer rather than publishing exploit details in an issue. This repository
does not yet publish program source, binaries or a software download service.
